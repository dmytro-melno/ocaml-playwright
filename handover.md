# Task Handover

**Goal**: Modify the generated Playwright OCaml bindings so that LSP hover types show up as `Playwright.Frame.t` instead of `Playwright.frame_type Playwright.obj`.

## Current State and Findings
1. `lib/hl.ml` is auto-generated by `tools/generate_hl.ml`.
2. Currently, there is no `lib/hl.mli` file. The compiler infers types directly from `hl.ml`, resulting in exposed internal representation types (`frame_type obj`).
3. To hide these internals and show `Playwright.Frame.t`, we need to generate an `hl.mli` interface.
4. Because modules in Playwright are mutually interdependent (e.g., `Page` returns `Frame.t` and `Frame` returns `Page.t`), the `.mli` file *must* declare the modules as mutually recursive:
   ```ocaml
   module rec Frame : sig
     type t = frame_type obj
     val page : t -> Page.t
   end
   and Page : sig
     type t = page_type obj
     val main_frame : t -> Frame.t
   end
   ```
5. Interestingly, the implementation file `lib/hl.ml` does **not** need to use `module rec`. Standard non-recursive `module` declarations in `.ml` perfectly satisfy a mutually recursive `.mli` signature.
6. Generating exact signatures manually inside `tools/generate_hl.ml` is tedious. A more robust approach we tested successfully:
   - Generate `lib/hl.ml`.
   - Use the compiler to infer the signature (e.g. `ocamlc -i lib/hl.ml > hl_inferred.mli`).
   - Post-process `hl_inferred.mli` using a regex script to:
     - Strip internal prefixes (e.g., `Playwright__`).
     - Change `module X : sig` to `module rec X : sig` (for the first) and `and X : sig` (for the rest).
     - Replace `([a-z0-9_]+)_type obj` with `Mod_name.t` in function signatures.
     - Keep `type t = xxx_type obj` intact inside the module signatures.
   - Save the resulting output as `lib/hl.mli`.

## Next Steps
1. The most straightforward path forward is to integrate the `.mli` generation directly into the build pipeline or `tools/generate_hl.ml`.
2. You can either:
   - Enhance `tools/generate_hl.ml` to natively emit `lib/hl.mli` alongside `lib/hl.ml` (this requires duplicating the signature generation logic but keeps the build simple).
   - Create a post-processing script and hook it into the `dune` build process to automatically generate `hl.mli` from `hl.ml`.
3. Pick one of the approaches, implement it, verify the build (`dune build`), and verify the tests. Ensure LSP hovers show `Playwright.Page.t`, etc.
